title: "AgentScope 2.0 とは？"

AgentScope Java 2.0 は、「エージェントを構築する」ためのツールキットから、**本番環境でエージェントを稼働させる**ための完全なプラットフォームへの大きな飛躍です。改善点は3つの重点領域に分類され、それぞれが異なる課題を解決します。

:::{note}
AgentScope Java 2.0 は、ほとんどのユーザーがスムーズにアップグレードできるよう、可能な限り 1.x との互換性を維持することを目指していますが、コアの抽象化、API、アーキテクチャへの大幅な改善とともに、API レベルの破壊的変更も導入しています。完全な移行ガイドは [V1 移行ガイド](./change-log.md) を参照してください。
:::

## 1 · Harness エンジニアリング — 長時間稼働する複雑なタスクのために構築

素の ReAct ループは1つの推論ターンを解決するだけです。実世界のタスクは何時間も実行され、状態を蓄積し、永続的なスキルを必要とします。**Harness** はエージェントが無期限に信頼性を保ち、能力を蓄積し、手作業によるコンテキスト操作なしに複雑な仕事を完了できるようにするためのエンジニアリング足場を構築します — 推論コアには手を加えず、能力を層として重ねます。

::::{grid} 2

:::{grid-item-card} 自己進化とスキルリポジトリ
:link: harness/skill.html

成功したパターンは `workspace/skills/` に Markdown スキルとして保存され、ステップごとに読み込まれ、セッション間で共有されます — ノウハウが実行を重ねるたびに蓄積されます。
:::

:::{grid-item-card} 階層化されたメモリ管理
:link: harness/memory.html

3つの階層: コンテキスト内の会話、エージェントがキュレーションする `MEMORY.md`、そしてディスク上のファクトログ。自動コンパクションがプロンプトを有界に保ち、`memory_*` ツールが明示的な想起を提供します。
:::

:::{grid-item-card} サブエージェント
:link: harness/subagent.html

Markdown 仕様で子エージェントを宣言し、`agent_spawn` / `agent_send` を介して同期またはバックグラウンドで実行します。バックグラウンドの結果は `system-reminder` を通じてプッシュバックされます — ポーリングは不要です。
:::

:::{grid-item-card} 自動コンテキスト管理
:link: harness/compaction.html

構造化コンパクションが目標、状態、発見、次のステップを保持します。サイズの大きいツール結果はディスクにオフロードされ、コンテキストオーバーフロー時の再試行がセーフティネットとなります。
:::

:::{grid-item-card} 複雑なタスクのための Plan Mode
:link: harness/plan-mode.html

長時間タスクのための読み取り専用のプランニング状態。プランは `workspace/plans/` 配下に永続化され、実行を駆動します — 意図とアクションを分離した状態に保ちます。
:::

:::{grid-item-card} 基盤としてのワークスペース
:link: harness/workspace.html

ペルソナ、知識、スキル、サブエージェント仕様、セッションログ — すべてディスク上の Markdown / JSON として存在し、毎ターン自動的にプロンプトへ注入されます。
:::

::::

## 2 · エンタープライズグレードの分散デプロイ

本番環境のエージェントは、多数のテナントにサービスを提供し、信頼できないツールコードを安全に実行し、進行中のコンテキストを失うことなくローリング再起動を乗り切らなければなりません。AgentScope 2.0 は**ステートレスな水平スケーリング**のために構築されています。どのレプリカでも任意のユーザーの完全なコンテキストを引き継ぐことができ、サンドボックスの状態はプロセスをまたいで再開され、パーミッションゲートと多次元の分離がすべてのテナントのデータを分離した状態に保ちます。

::::{grid} 2

:::{grid-item-card} マルチテナント分離
:link: building-blocks/context.html

`session` / `user` / `agent` / `org` にわたって状態を分離します。`RuntimeContext` のキーはワークスペースのパス、KV 名前空間、サンドボックスの状態スロットへと流れていきます。
:::

:::{grid-item-card} セキュアなサンドボックス実行
:link: harness/sandbox.html

ツールは隔離された環境 — ローカルサブプロセス、Docker、またはリモート AgentRun — で実行され、スナップショット/再開機能により長時間のジョブが再起動を乗り越えて生き残ります。
:::

:::{grid-item-card} ツールのパーミッション制御
:link: building-blocks/permission-system.html

静的ルール、ツールのカテゴリ、入力分析に基づく3状態エンジン(許可 / 承認 / 拒否)。機微なツールは人間の承認を必要とします — HITL はファーストクラスです。
:::

:::{grid-item-card} グレースフルな起動/停止とセッション復旧
:link: building-blocks/context.html

同じ `(userId, sessionId)` を使えば、任意のプロセスで会話全体を再開できます。`AgentStateStore`(インメモリ / JSON ファイル / MySQL / Redis)がゼロダウンタイムのローリングデプロイとクラッシュリカバリを支えます。
:::

## 3 · 基盤フレームワーク — よりリーンで開発者フレンドリーなコア

最下層は再設計されました。メッセージ、イベント、拡張モデルは、より小さく、より直交的で、より扱いやすくなりました — そして HITL とイベントストリーミングはもはや後付けの追加機能ではなく、フレームワークの動作そのものの一部です。

::::{grid} 2

:::{grid-item-card} イベントストリーミング、組み込み
:link: building-blocks/message-and-event.html

すべてのステップ — モデル呼び出し、テキスト差分、ツール実行、ツール結果 — が、1つのストリーム上の型付きイベントとして現れます。一度購読すれば、UI がリアルタイムに追従します。
:::

:::{grid-item-card} よりシンプルなメッセージモデル
:link: building-blocks/message-and-event.html

テキスト、ファイル、画像、音声、動画、思考、ツール結果 — すべてが1つの `ContentBlock` 形状です。ロールに厳密な構築が、ビルド時に不正な形式のメッセージを検出します。
:::

:::{grid-item-card} フックではなく Middleware
:link: building-blocks/middleware.html

5つのステージ(`onAgent` / `onReasoning` / `onActing` / `onModelCall` / `onSystemPrompt`)が v1 の緩いフックに取って代わります。各関心事は自分の層にとどまり、きれいに合成されます。
:::

:::{grid-item-card} Human-in-the-loop、ファーストクラス
:link: building-blocks/permission-system.html

ツールの引数を確認したり、機微なアクションを承認したり、実行途中で外部システムに引き渡したりできます。エージェントは停止した箇所で正確に一時停止・再開します — 足場は不要です。
:::
