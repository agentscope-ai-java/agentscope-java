# AgentScope로 금융급 Agent 기반 구축하기: FinXScope 실천기

> 저자: Meng Chen (Bantang), Wen Jun (Siyue), Ling Lezhen (Lezhen), Xu Lei (Chongshu), Lin Yuan (Niren)

## 01 제품 포지셔닝과 핵심 비전

### 1.1 FinXScope란 무엇인가

FinXScope는 Alibaba Cloud New Finance Technical Services 팀이 **AgentScope Java 위에 구축한 금융급, AI 네이티브 에이전트 기반**입니다. 전체 Agent Harness 시스템의 핵심 구성 요소로서, FinXScope는 에이전트 오케스트레이션, 도구 통합, 다중 모델 접근, 확장 가능한 런타임 등 AgentScope Java의 성숙한 역량을 충분히 재사용하는 동시에, 그 위에서 금융 산업의 컴플라이언스, 보안, 고가용성 요구사항을 충족하기 위한 심층 커스터마이징과 강화를 수행합니다. 전체 Agent Harness 시스템은 FinXScope 런타임 기반, AI 서비스 자산 플랫폼, 전체 링크 평가 플랫폼, 운영 관리 플랫폼으로 구성되며, FinXScope가 에이전트 실행과 관리라는 가장 핵심적인 역할을 담당합니다.

FinXScope의 핵심 포지셔닝을 이해하려면 네 가지 핵심 차원을 파악해야 합니다.

**한 문장으로 말하면**: FinXScope는 금융급, AI 네이티브 에이전트 기반의 핵심 엔진입니다. 전문 서비스 팀이 금융 기관과 깊이 공동 창조하여, 실제 엔터프라이즈 시나리오를 중심으로 금융급 요구사항을 충족하는 AI 네이티브 애플리케이션 구축, 실행, 운영 시스템을 만듭니다. 이를 기반으로 구축된 Agent 애플리케이션은 사용자가 한 문장으로 목표를 설명하기만 하면, 시스템이 자율적으로 경로를 계획하고 수백 개의 스킬을 동적으로 오케스트레이션하여 작업을 완료함으로써, "대화가 곧 서비스"라는 새로운 상호작용 패러다임을 진정으로 실현합니다.

### 1.2 고객 진행 상황과 시장 검증

출시 이후 FinXScope는 여러 금융 기관으로부터 강한 관심을 끌었으며 실질적인 협업 성과를 거두었습니다. 10개의 선도적인 금융 고객사에서 프로덕션에 배포되었으며, 20개 이상의 추가 고객사에 전달되고 있고, 국유 대형 은행, 주식제 은행, 보험사, 증권사 등 다양한 금융 업종을 아우르는 60개 이상의 금융 고객 기반을 확보하고 있습니다.

실제 배포 시나리오는 자산관리, 고객 매니저 역량 강화, 지능형 언더라이팅, 컴플라이언스 심사, 투자 리서치 분석 등 핵심 금융 비즈니스를 포괄합니다. 이미 프로덕션에 배포된 프로젝트 중 AI 네이티브 앱은 수천만 명의 사용자 기반에 도달했으며, 이는 실제 프로덕션 환경에서 FinXScope의 안정성과 비즈니스 가치를 입증합니다.

이러한 실천은 하나의 핵심 판단을 검증합니다: 금융 기관이 필요로 하는 것은 또 하나의 챗봇 프레임워크가 아니라, 개념 증명(POC)에서부터 대규모 프로덕션에 이르기까지 엔터프라이즈급 에이전트를 진정으로 지원할 수 있는 런타임 기반입니다.

## 02 산업 배경과 도전 과제

### 2.1 "기능 내비게이션"에서 "대화가 곧 서비스"로의 패러다임 도약

금융 AI는 근본적인 패러다임 전환을 겪고 있습니다. 2024년 이후 Manus, Claude Code, Hermes Agent로 대표되는 자율 에이전트 제품들이 글로벌 시장의 관심에 불을 붙였고, OpenClaw는 3개월 만에 23만 개 이상의 GitHub 스타를 얻으며 현상급 프로젝트가 되었습니다. 이러한 획기적인 사건들은 대형 모델이 "채팅 어시스턴트"에서 복잡한 작업을 자율적으로 계획하고 실행할 수 있는 "업무 파트너"로 진화했음을 증명합니다.

![에이전트 제품의 획기적 사건들](https://mmbiz.qpic.cn/mmbiz_png/bvDbzNRia8j31Nbiagg96SjGyRY33Lv0pO0hYAbuuCEVcQiccvH4HhESAULoxjRaKhCVUFKDicWt8v6rNAoJVxLicjaFDic5xeJXm4gMk02NfOb74/640?wx_fmt=png&from=appmsg)

금융 산업에게 이러한 변화의 영향은 심대합니다. 지능형 서비스 개발의 전통적인 경로는 기존 시스템 위에 AI 역량을 "쌓아 올리는" 것입니다: AI는 전통적인 워크플로의 보조 도구처럼 위치하며 기존의 서비스 경로를 깨뜨리지 않습니다. 사용자는 여전히 계층적 메뉴, 버튼, 폼 사이를 수동으로 탐색해야 하며 — 유일한 차이는 "AI Q&A" 진입점이 추가되었다는 점뿐입니다. 이는 어색한 상황으로 이어집니다: 고객은 이른바 "지능형 서비스"를 사용하지만, 사용 패턴과 경험은 본질적으로 기존과 다르지 않습니다.

그러나 대형 모델의 역량이 결정적인 임계값을 넘어서면서, AI는 비즈니스 프로세스에 참여하고 심지어 이를 주도할 수 있는 능력을 갖추게 되었습니다. 이는 금융 기관의 AI에 대한 기대가 근본적으로 바뀌었음을 의미합니다: 더 이상 단순히 고정된 워크플로를 자동화하는 것이 아니라, AI가 사용자 의도를 자율적으로 이해하고, 엔터프라이즈급 금융 서비스 자산을 동적으로 오케스트레이션하여 고객의 복잡한 문제를 해결하기를 바랍니다.

![금융 기관의 AI에 대한 기대의 근본적 변화](https://mmbiz.qpic.cn/sz_mmbiz_png/bvDbzNRia8j2HL1oMgRlGCK7LY8xuE4IOHpxavn3FuOibq4DseicvvcSuNHbLTflbKKmRaIibXWxn13dpYMQiaAlU5CRuPiauDjrNKMibOY9wpXx28/640?wx_fmt=png&from=appmsg)

이 도약의 본질은: "엔터프라이즈 기능 중심"에서 "사용자 문제 중심"으로의 전환입니다 — 사용자는 더 이상 시스템에 어떤 기능이 있는지, 어떤 흐름을 따라야 하는지 알 필요가 없습니다. 그저 목표를 직접 설명하면, AI가 이해에서 실행까지 전체 프로세스를 자율적으로 완료합니다. 이것이 바로 "대화가 곧 서비스"라는 새로운 패러다임입니다.

### 2.2 금융 기관이 Agent를 구축할 때 직면하는 구조적 도전 과제

Ernst & Young의 "AI 뱅킹 백서" 분석에 따르면, 은행업에서 AI 기술의 규모화된 배포는 이미 전략적 긴급성을 지니고 있습니다. PwC의 2026년 금융 AI 설문조사 역시 은행과 보험사가 AI 거버넌스에서 가장 중요하게 여기는 것이 추적 가능성과 설명 가능성이라고 지적합니다. 그러나 금융 기관이 POC 검증에서 규모화된 프로덕션으로 나아가면서, 일련의 심층적인 구조적 도전 과제에 직면하게 되며 — 이것이 바로 FinXScope가 해결하도록 설계된 문제들입니다.

![금융 기관이 Agent를 구축할 때 직면하는 구조적 도전 과제](https://mmbiz.qpic.cn/mmbiz_png/bvDbzNRia8j38qaZ1xD0GDb7vPOm8WdyuiaQxeCmpqIMC54TLxyaQSqObiclrkLPNgS2kTBic4np1rjmibe0SUnx1plpnUrqHeUlWicMHukszb2wY/640?wx_fmt=png&from=appmsg)

위 도전 과제들의 본질은 시스템적인 문제입니다: 금융 기관이 필요로 하는 것은 어떤 단일 지점 역량의 강화가 아니라, 완전한 에이전트 런타임 기반입니다.

간과하기 쉬운 사실 하나: 에이전트의 최종 비즈니스 성과는 대형 모델 자체의 역량에만 전적으로 좌우되지 않으며, 그 실행을 담당하는 기반(Agent Harness)의 품질에도 동등하게 의존합니다. 의도가 정확히 이해되는지, 도구가 올바르게 오케스트레이션되는지, 컨텍스트가 효과적으로 관리되는지, 실행 프로세스가 신뢰할 수 있고 제어 가능한지 — 이러한 "모델을 넘어서는" 엔지니어링 역량이야말로 에이전트가 실제 시나리오에서 안정적으로 가치를 전달할 수 있는지를 결정합니다. 동일한 대형 모델이라도 품질이 다른 기반 위에서 실행되면 완전히 다른 비즈니스 성과를 낳을 수 있습니다. 이것이 금융 기관이 전문가급 Agent Harness를 필요로 하는 근본적인 이유입니다.

## 03 AI 네이티브 6계층 아키텍처

### 3.1 6계층 아키텍처 설계

FinXScope는 전체 Agent Harness 시스템의 핵심 엔진이며, 금융 산업을 대상으로 한 최초의 엔터프라이즈급 에이전트 런타임 기반이기도 합니다. 이는 흩어진 기술 구성 요소가 아니라 체계적이고 완전한 역량 조합을 제공합니다: Alibaba에서 대규모로 검증된 AgentScope 프레임워크를 기반으로, 10가지 완전히 자체 개발된 핵심 역량과 금융급 강화를 추가하여, 견고한 기술 기반과 금융 시나리오에 대한 빠른 적응력을 모두 갖춘 에이전트 런타임 플랫폼을 형성합니다. FinXScope를 중심으로 Agent Harness 시스템은 AI 서비스 자산 플랫폼(FinXSkillHub), 전체 링크 평가 플랫폼(FinXVantage), 운영 관리 플랫폼으로 더욱 확장되어, 함께 개발과 실행에서 지속적인 최적화에 이르는 에이전트의 전체 생애주기를 커버합니다. FinXScope의 6계층 아키텍처는 이 시스템의 기술 구현 골격일 뿐만 아니라, AI 네이티브 시대를 위한 엔터프라이즈 애플리케이션 아키텍처의 완전히 새로운 정의와 규범이기도 합니다.

![FinXScope의 6계층 아키텍처](https://mmbiz.qpic.cn/mmbiz_png/bvDbzNRia8j2Oqs21qftQibzJXYkH4MTwxau2HRrTJYUZGGbor1ceehlhicr57K0UZoCfXBRQibkXWkUY4k3JjoWszKciah8nAXq9mia88wLRb478/640?wx_fmt=png&from=appmsg)

왜 엔터프라이즈 아키텍처를 재정의해야 할까요? 전통적인 엔터프라이즈 아키텍처(SOA, 마이크로서비스)는 "인간이 시스템을 조작한다"는 패러다임을 중심으로 설계되었습니다: 인간이 인터페이스를 통해 작업을 시작하고, 시스템이 미리 설정된 흐름에 따라 실행하며, 결정론적 결과를 반환합니다. 그러나 AI 네이티브 패러다임 아래에서는 "AI가 자율적으로 작업을 계획하고 실행하는 것"이 핵심 원동력이 됩니다. 이는 모든 서비스 역량, 데이터 자산, 기능 구성 요소를 "AI에 의해 더 잘 이해되고 호출될 수 있는 방법"을 중심으로 재조직할 것을 요구합니다. 이는 기존 아키텍처 위에 덧대는 패치가 아니라, 근본적인 설계 패러다임의 전환입니다.

## 04 핵심 역량 심층 분석

아래의 10가지 핵심 역량은 FinXScope의 기술적 해자입니다. 여기에는 완전히 자체 개발된 독창적 역량과 AgentScope 위에 구축된 심층 강화가 모두 포함됩니다. 이러한 역량은 실제 금융 고객 시나리오의 엄격한 요구사항에서 비롯되었으며, 여러 프로덕션 환경에서 다듬어지고 검증되었습니다.

### 4.1 의도 엔진: 금융 시맨틱의 정밀한 이해

**시나리오 페인 포인트**: 금융 대화 시나리오에서 사용자의 표현은 종종 구어적이고, 모호하며, 컨텍스트 의존도가 높습니다. "마오타이 요즘 어때?"는 "구이저우 마오타이(600519)의 최근 주가 추세"로 이해되어야 하며; "어제 얘기한 그 상품 5만 원어치 사줘"는 대화 이력에서 완전한 지시를 복원해야 합니다. 전통적인 키워드 매칭이나 얕은 분류 모델은 이러한 복잡한 금융 대화에서 명백한 한계를 드러냅니다.

![금융 대화 시나리오의 시맨틱 이해 과제](https://mmbiz.qpic.cn/mmbiz_png/bvDbzNRia8j1PBJxG0U8nZXIhPwwLQQagkMiarjKL8VzEAcGC7ILibGITGkF6xlWY4Niamfkn078nbDBWhD8cUo2r0c8Dw2MiaQmQlAibUPSuTicicE/640?wx_fmt=png&from=appmsg)

**해결책**: FinXScope의 의도 엔진은 완전한 4단계 처리 파이프라인을 구현합니다. 각 단계는 독립적으로 켜고 끌 수 있으며 유연하게 구성할 수 있어, "모듈화되고 구성 가능한 금융 의도 엔진"을 형성합니다.

**1단계**: NER 엔터티 인식 — 금융 도메인 사전과 규칙 엔진을 기반으로, 주식 코드, 기업명, 금액, 시간, 백분율 등 금융 엔터티를 자동으로 인식합니다. 비동기 처리와 소형 모델 추론이 고성능(밀리초 단위 응답)을 보장하며, 구성 가능한 사전 메커니즘이 기업이 정의하는 엔터티 유형 확장을 지원합니다.

**2단계**: 쿼리 재작성 — 구어적 입력을 구조화된 쿼리 요청으로 변환합니다. 재작성 파이프라인은 네 개의 프로세서를 체인으로 연결합니다: 컨텍스트 강화(대화 이력과 사용자 프로필에서 컨텍스트를 추출하여 상호참조 해소를 달성), 용어 표준화("연간 수익" → "연간 수익률"), 시맨틱 교정(모호함과 오류 수정), LLM 재작성(필요 시 대형 모델을 호출하여 더 명확한 구조화된 표현 생성). 재작성 규칙은 관리 콘솔에서 온라인 구성을 지원합니다.

**3단계**: 의도 분류 — 동적 의도 트리를 기반으로 다층 의도 판정을 수행합니다. LLM 지능형 분류(고정밀)와 규칙 기반 폴백(고성능) 간의 자동 전환을 지원합니다. 의도 트리는 관리 콘솔에서 온라인 구성과 버전 관리를 지원하며, 런타임 동적 오버라이드를 지원합니다.

**4단계**: 스킬 매핑 — 인식된 의도를 기반으로 해당 스킬로 정밀하게 라우팅합니다. 다중 스킬 조합과 우선순위 구성을 지원하며, 매핑 관계는 관리 콘솔에서 온라인으로 구성할 수 있습니다.

의도 트리 라우팅 외에도, 의도 엔진은 Skill 문서를 기반으로 한 LLM 자율 계획 모드도 지원합니다. 사용자의 질문이 의도 트리로 정밀하게 매칭될 수 없을 때, 시스템은 자동으로 LLM 자율 계획으로 전환합니다: 대형 모델은 SkillPool 내 모든 사용 가능한 스킬의 문서(SKILL.md)를 기반으로, 어떤 스킬을 어떤 순서로 호출할지 자율적으로 결정합니다. 두 모드는 동일한 에이전트 내에 공존하며, 엔진이 질문의 특성에 따라 자동으로 라우팅합니다.

**2.0의 새로운 기능**: 호출자가 요청 파라미터를 통해 사전 설정된 의도 트리를 오버라이드할 수 있도록 지원하여 멀티테넌트 시나리오에서 차별화된 의도 전략을 가능하게 하고; 의도 스위치 추적을 지원하며; 의도 트리 관리 API가 전체 CRUD와 버전 롤백을 지원합니다.

### 4.2 3계층 메모리 시스템: 프롬프트 엔지니어링에서 컨텍스트 엔지니어링으로의 진화

**시나리오 페인 포인트**: 전통적인 AI 시스템은 메모리가 전혀 없거나(모든 대화가 처음부터 시작), 원시 메시지만 축적할 뿐(고가치 정보를 추출할 수 없음), 메모리 구현이 비즈니스 로직과 깊이 결합되어 있어 통합된 읽기/쓰기 인터페이스와 생명주기 관리가 부족합니다.

![3계층 메모리 시스템](https://mmbiz.qpic.cn/sz_mmbiz_png/bvDbzNRia8j2jUjCICaLeYspfgU4pOkxiaF02s39Pzb19TAWuMWJ4FV7XVHZs4iad6eiaUWSj7cQacq0hYiaZ2FDQmHLZiaiaUYNWoopFncD6Tk6nc/640?wx_fmt=png&from=appmsg)

**해결책**: 프롬프트 엔지니어링은 "좋은 프롬프트를 작성하는 방법"에 초점을 맞추는 반면, 컨텍스트 엔지니어링은 "LLM이 수신하는 모든 컨텍스트 정보를 체계적으로 관리하는 방법"에 초점을 맞춥니다: 컨텍스트의 품질과 구성이 에이전트의 의사결정 품질을 직접적으로 결정합니다. 3계층 메모리는 세 개의 독립된 "저장소"가 아니라, 완전한 "저장 → 압축 → 회상 → 주입" 실행 주기입니다.

**단기 메모리(STM)**: 대화 수준 컨텍스트의 윈도우 관리와 지능형 압축. STM은 슬라이딩 윈도우 메커니즘을 사용하여 현재 세션의 대화 턴을 관리합니다. 대화가 계속되어 컨텍스트가 점차 토큰 임계값을 넘어 팽창하면, STM은 지능형 압축을 트리거합니다: LLM 요약이 우선시되며(대형 모델이 대화에서 핵심 정보와 결정 지점을 추출하여 간결한 요약으로 압축), 규칙 기반 요약이 폴백 전략으로 사용됩니다(시간 감쇠를 기반으로 오래되고 중요도가 낮은 메시지를 폐기). 압축된 요약은 원본 메시지를 대체하고 대화에 계속 참여하여, 매번 모델에 주입되는 컨텍스트가 핵심 시맨틱을 유지하면서도 지나친 길이로 인해 추론 품질을 해치지 않도록 보장합니다. 다차원 용량 제어(턴 수 제한, 토큰 제한, 시간 제한)가 함께 작동합니다.

**2.0의 업그레이드**: STM은 Redis 영속화를 지원하여 인스턴스 간 세션 복구를 가능하게 합니다.

**장기 메모리(LTM)**: 세션 간 지식의 구조화된 저장과 시맨틱 회상. LTM은 PostgreSQL + pgvector를 기반으로 영속적인 벡터 저장소를 구현합니다. 각 대화가 끝난 후, 시스템은 상호작용에서 어떤 정보가 장기적 가치를 가지는지 자동으로 평가하고(LLM 기반 중요도 채점을 통해 중복되고 가치가 낮은 콘텐츠를 필터링), 가치 있는 정보를 LTM으로 벡터화합니다. 새로운 대화가 시작되면 시스템은 현재 사용자 입력을 벡터화하고 시맨틱 유사도를 통해 가장 관련성 높은 과거 조각을 검색합니다(예: "사용자가 지난주에 문의한 펀드 상품", "사용자가 표현한 투자 선호도"). 키워드 검색(시간 감쇠 채점 포함)도 보완 채널로 지원되며, 벡터 검색이 실패할 때 자동으로 폴백됩니다. 회상된 메모리 조각은 현재 대화의 컨텍스트에 주입되어, 에이전트가 세션을 넘어 핵심 정보를 "기억"할 수 있게 합니다.

**2.0의 업그레이드**: LTM은 완전히 PostgreSQL로 마이그레이션되었으며 클러스터 배포를 지원합니다.

**UserProfile**: LTM 위에 구축된 구조화된 금융 속성 계층. UserProfile은 세 번째로 독립된 유형의 "메모리"가 아니라, 장기 상호작용에서 자동으로 추출되고 업데이트되는 구조화된 사용자 인지입니다. LTM에 흩어져 있는 상호작용 정보를 표준화된 금융 속성으로 정제합니다: 정적 속성(나이, 직업, 자산 규모), 동적 속성(위험 등급 변화, 투자 선호도 진화), 행동 선호도(상호작용 스타일, 의사결정 습관), 태그 시스템(고액 자산가, 보수적, 기술 섹터 집중 등). 매 상호작용마다 자동으로 업데이트되며, 전체 프로필은 시스템 프롬프트에 주입되어 대화 전략을 안내합니다. UserProfile의 런타임 주입은 서로 다른 사용자에게 완전히 다른 서비스 전략을 제공합니다 — 동일한 "펀드 추천" 질문에 대해, 보수적 사용자와 공격적 사용자는 완전히 다른 상품 조합과 표현 방식을 받습니다.

**비동기적이고 감지 불가능함**: 세 메모리 계층의 읽기/쓰기 작업은 완전히 비동기적으로 이루어지며 메인 플로우의 응답 속도에 영향을 주지 않습니다. 사용자가 인지하는 것은 즉각적인 응답이며, 시스템은 백그라운드에서 메모리 평가, 압축, 저장, 프로필 업데이트를 조용히 완료합니다.

### 4.3 이중 모드 지능형 실행 아키텍처: 유연성과 제어 가능성의 통합

시나리오 페인 포인트: 금융 비즈니스 시나리오의 복잡도 범위는 매우 넓습니다 — 단순한 잔액 조회부터 복잡한 투자 포트폴리오 분석까지. 단일 실행 모드로는 모든 시나리오를 커버할 수 없습니다: 순수 자율 계획 모드는 단순한 시나리오에서 비효율적이고 예측 불가능하며, 순수 워크플로 모드는 개방형 질문에는 너무 경직됩니다.

![이중 모드 지능형 실행 아키텍처](https://mmbiz.qpic.cn/sz_mmbiz_png/bvDbzNRia8j3KDYmZys4TiaJn3Vq3GkFzUcHKfG6q1vQzUz7zicly0xycxiazE458jWUpepIFS91Xet4EBbVfuwy21n9qpQq7nKLISeEaLomCDQ/640?wx_fmt=png&from=appmsg)

**해결책**: 먼저 두 가지 실행 모드를 지원한 다음, 공유 실행 기반을 통해 두 모드를 융합합니다.

**OneAgent 모드**: 자율 지능형 실행. ReAct(추론-행동) 루프를 기반으로, 단일 에이전트가 폐루프에서 자율적으로 작업을 계획하고 실행하도록 합니다. 각 단계에서 AI는 "생각 → 행동 → 관찰" 사이클을 거치며, 대형 모델의 창의성과 추론 능력을 최대한 발휘합니다 — 개방형, 탐색형 작업에 적합합니다.

**Multi-Agent 모드**: 협업 오케스트레이션 실행. 2.0에서 새롭게 구축된 통합 워크플로 실행 엔진으로, 여덟 가지 오케스트레이션 전략을 지원합니다: 병렬 실행(Parallel), 순차 실행(Sequential), 반복 실행(Loop), 메시지 센터(MsgHub), 토론 모드(Debate), 그래프 오케스트레이션(Graph, DAG 기반), 동적 라우팅(Routing), 감독자 모드(Supervisor). 각 전략은 표준화된 인터페이스를 구현하며 스트리밍 출력을 지원합니다.

**핵심 혁신**: 공유 실행 기반이 두 모드의 심층 융합을 가능하게 합니다. 두 실행 모드 자체를 구현하는 것이 가장 어려운 부분은 아닙니다. 진짜 기술적 하이라이트는: OneAgent와 Multi-Agent가 동일한 통합 실행 엔진(AgentProcessEngine)을 기반으로 공유한다는 점입니다. 이는 두 모드가 권한 검증, 감사 추적, 실행 관리와 같은 횡단 관심사에서 일관성을 유지함을 의미합니다 — 실행 모드를 전환해도 금융급 보증을 희생하지 않습니다.

바로 이 공유 실행 기반 덕분에, FinXScope는 또 다른 혁신을 통해 한 걸음 더 나아갈 수 있습니다 — 워크플로를 OneAgent에 마운트하는 것입니다. MountableResource 메커니즘을 통해 Multi-Agent 워크플로는 도구(Tool)로 캡슐화되어 OneAgent가 자율 추론 중 필요에 따라 호출할 수 있습니다. AI는 언제 결정론적 워크플로(예: 컴플라이언스 심사 하위 프로세스)를 실행할지 자율적으로 결정하며, 워크플로가 완료되면 결과가 OneAgent로 반환되어 추론을 계속합니다. 이러한 "자율 지능 + 결정론적 흐름"의 융합이 가능한 이유는, 정확히 두 모드가 동일한 실행 엔진에서 실행되기 때문입니다 — 컨텍스트가 매끄럽게 전달될 수 있고, 이벤트가 모드 간에 전파될 수 있으며, 감사가 통합적으로 기록될 수 있습니다. 워크플로 일시 중단/재개와 하위 프로세스 이벤트 패스스루를 지원합니다(메인 Agent가 정보를 중계함으로써 발생하는 정보 감쇠와 추가 지연을 피함).

### 4.4 통합 실행 엔진: 에이전트의 "운영체제 커널"

**시나리오 페인 포인트**: 각 에이전트가 자체적인 실행 로직을 구현하면 코드 중복, 동작 불일치, 불완전한 감사로 이어지며 — 이는 금융급 시나리오에서 용납할 수 없는 컴플라이언스 리스크입니다. 서로 다른 Agent들은 컨텍스트 조립 방식이 고르지 않고, 메모리 읽기/쓰기 타이밍이 일관되지 않으며, 예외 처리 체인이 임시방편적이어서 전체 링크 로그를 추적할 수 없게 만들고, 도구 호출에 통합된 인터셉션이 없게 됩니다. 이는 "모든 의사결정 단계를 추적 가능하게" 해야 한다는 감사 요구사항을 충족하지 못하며, 다중 오케스트레이션 모드 하에서 유지보수와 진화 비용을 크게 증가시킵니다.

**해결책**: AgentProcessEngine이 통합된 실행 진입점 역할을 합니다. 전체 엔진은 사전 공통 계층, 전략 라우팅 계층, 사후 공통 계층을 포함하며, "통합 진입 → 통합 스케줄링 → 통합 마무리"의 폐루프 아키텍처를 형성합니다.

**사전 공통 계층**:

- 권한 검증: User-Agent-Skill 3단계 검증.
- 입력 전처리: 파일 ID와 실행 식별자를 통합적으로 완성하여, 이후 모든 계층이 완전하고 추적 가능한 입력을 얻을 수 있도록 보장.
- 컨텍스트 로딩: 과거 메시지로부터 단기 메모리(STM)를 조립하고, MemoryManager에서 관련 장기 메모리(LTM)를 회상하며, 사용자 프로필에서 위험 선호도 등 정적 속성을 읽어, 이를 실행 컨텍스트에 통합적으로 주입.
- 감사 시작: 전체 링크 구조화 로그를 열고, 의도 결정 체인과 지연 시간 메트릭을 기록하여, 이후 인터셉션 지점에 통합된 컨텍스트 앵커를 제공.

**전략 라우팅 계층**:

- 유연한 전략 선택: patternType에 따라 실행 전략(OneAgent ReAct / 여덟 가지 Multi-Agent 오케스트레이션)을 자동으로 선택.
- MountableResource 생명주기: 메모리 매니저, Toolkit, Skill 패키지, 사전 컴파일된 그래프 등 "마운트 가능한 리소스"는 전략이 시작될 때 부착되고 종료될 때 해제되며, 모두 실행 컨텍스트에 의해 통합적으로 관리됨.

**사후 공통 계층**:

- 결과 포맷팅: 모든 전략의 출력이 표준 AG-UI 이벤트 스트림으로 통합 수렴됨 — 프론트엔드용 단일 프로토콜.
- 메모리 쓰기: 사용자의 원본 텍스트 + 어시스턴트의 전체 응답 + 메타데이터(세션, 재작성된 텍스트, 의도 유형, 매칭된 Skill, 도구 호출 세부사항)가 비동기적으로 STM / LTM / UserProfile에 다시 기록되며, 사용자 프로필은 매 상호작용마다 지속적으로 정교해짐.
- 감사 종료: 완료되지 않은 스트리밍 메시지 세그먼트를 닫고, 종료 상태 이벤트를 발행하며, 구조화된 로그(인스턴스, 모드, 지연 시간, 텍스트 길이)를 출력하여, 사전 계층의 traceId와 함께 폐루프를 완성.
- 메트릭 수집: Prometheus 메트릭 엔드포인트가 연결되어 엔진 총 지연 시간, 단계별 지연 시간, LLM 호출 횟수 등의 메트릭을 수집.

동기, 스트리밍, AG-UI의 세 가지 실행 모드를 완전히 지원합니다. 완전한 인터셉터 체인(12개 인터셉션 지점)이 커스텀 로직 주입을 지원합니다. 실행 전체에 걸쳐 의사결정 체인, 도구 호출, Skill 로그가 자동으로 기록되어 금융 감사와 컴플라이언스 요구사항을 충족합니다.

**2.0의 새로운 기능**: 런타임 모델 오버라이드, Skill 수준 타임아웃 구성과 재시도 전략, 실행 컨텍스트의 투명한 인스턴스 간 마이그레이션.

- 런타임 모델 오버라이드: 시스템 프롬프트, 모델 유형, 스킬 등이 핫 업데이트를 지원하며; 동일한 Agent 구성이 사용자/시나리오별로 동적으로 변형될 수 있음.
- Skill 수준 타임아웃과 재시도: Skill 단위로 독립적인 타임아웃 임계값과 재시도 전략을 구성하여, 롱테일 도구가 전체 대화 체인을 지연시키는 것을 방지.
- 실행 컨텍스트의 투명한 인스턴스 간 마이그레이션: 다중 레플리카 배포에서, 어떤 인스턴스로 라우팅된 요청이든 상태를 복원할 수 있어, 카나리 배포와 장애 조치의 기반을 제공.

### 4.5 AG-UI 전체 링크 스트리밍 상호작용: 채널 전반에 걸친 일관된 실시간 서비스 경험

**시나리오 페인 포인트**: 전통적인 AI 애플리케이션의 "질문 하나 하고 30초 기다리는" 상호작용 모드는 사용자가 AI가 무엇을 하고 있는지 인지할 수 없게 만듭니다. 서로 다른 채널이 각자의 상호작용 프로토콜을 커스터마이징하면 경험 불일치와 높은 관리 비용으로 이어집니다. 한편 일부 금융 데이터는 구조화되어 있으며, 순수 텍스트 출력으로는 추세, 비교, 비율 등의 정보를 효과적으로 전달할 수 없습니다.

**해결책**: FinXScope는 AG-UI 표준 프로토콜을 완전히 채택합니다. Spring WebFlux 리액티브 스트리밍 아키텍처를 기반으로, SSE(text/event-stream)를 통해 전체 링크 비동기 스트리밍을 구현합니다. AG-UI 프로토콜은 15개의 세분화된 이벤트 유형을 정의하며, 추론 과정, 도구 호출, 중간 결과, 최종 출력의 완전한 상호작용 체인을 포괄합니다. AG-UI의 표준화된 상호작용은 네 가지 핵심 가치를 가져다줍니다.

**채널 간 재사용**: 새로운 채널이 연결될 때, 프론트엔드는 각 채널마다 상호작용 프로토콜을 커스터마이징할 필요 없이 통합 표준에 따라 AG-UI 이벤트 스트림을 소비하기만 하면 됩니다. 동일한 이벤트 스트림을 채널 프론트엔드 전반에서 직접 재사용할 수 있어, 관리 및 개발 비용을 크게 줄이고 단말기 간 일관된 지능형 서비스 경험을 보장합니다.

**프론트엔드-백엔드 분리**: 프론트엔드는 표준 이벤트 스트림만 소비하며; 백엔드가 모델을 전환하거나, 도구를 추가/제거하거나, 전략을 조정해도 프론트엔드는 변경이 필요하지 않습니다. 이는 백엔드가 독립적이고 빠르게 반복할 수 있게 하는 동시에, 프론트엔드는 표준 이벤트 유형에 대한 렌더링 역량만 유지하면 됩니다.

**통합 관측 가능성**: 모든 Agent가 동일한 이벤트 유형 집합을 기반으로 모니터링, 알림, 성능 분석됩니다. 이벤트 스트림은 자연스럽게 전체 링크 실행 추적 역량을 제공합니다.

**확장 가능한 도구 생태계**: 새로운 도구는 프로토콜에 따라 표준 이벤트를 발행하기만 하면 프론트엔드에 자동으로 인식되고 소비되며, 팀 간 조율된 변경이 필요하지 않습니다.

렌더링 계층에서는 여러 표준 렌더링 도구가 내장되어 있습니다(라인 차트, 막대 차트, 파이 차트, 메트릭 카드, 데이터 테이블, 볼륨 차트, 선택 가능한 목록, 확인 액션 카드 등), 플레이스홀더 방식의 증분 렌더링과 개인화된 컴포넌트 확장을 지원합니다.

**2.0의 새로운 기능**: workflow_command_agent가 자연어를 제어-조작 명령으로 변환하며; WorkflowToolRegistry는 프론트엔드가 컨트롤을 동적으로 선언하고 런타임에 에이전트가 호출할 수 있는 도구로 등록할 수 있게 합니다.

### 4.6 3계층 Skill 정의 시스템: 구성에서 코드까지의 점진적 복잡도 적응

**시나리오 페인 포인트**: 금융 비즈니스 스킬의 복잡도 범위는 넓습니다 — 단순한 환율 조회부터 복잡한 신용 승인까지. 단일 정의 방식으로는 간결함과 표현력을 동시에 만족시킬 수 없습니다.

**해결책**: 3계층 스킬 정의 시스템은 복잡도에 따라 진행됩니다.

**YAML 구성 파일(경량 쿼리형)**: 구성 파일에 스킬 이름, 설명, 연관된 도구, 콘텐츠를 선언합니다. 프레임워크가 시작 시 자동으로 읽고 일괄 등록하며, 코드가 전혀 필요하지 않습니다. 환율 조회, 잔액 조회와 같이 콘텐츠가 고정되고 로직이 단순한 스킬에 적합합니다.

**SKILL.md + 스크립트(중간 복잡도, "문서를 계약으로")**: skills 디렉터리 아래에 각 스킬마다 독립된 폴더를 만듭니다. 핵심은 SKILL.md 문서이며, 선택적으로 Python/Shell 스크립트가 동반됩니다. OneAgent는 언제 스킬을 호출할지, 파라미터를 어떻게 전달할지 결정할 때 전적으로 이 Markdown 문서에 의존하므로, 동작이 예측 가능하고 감사 가능합니다. 고객 인사이트, 상품 추천, 리스크 평가와 같은 중간 복잡도 시나리오에 적합합니다.

**Java @Bean 등록(복잡한 비즈니스 로직)**: 표준 Spring Bean 방식으로, 완전한 타입 검사와 IDE 지원을 제공하며, 저수준 도구(다단계 트랜잭션 래퍼, 강한 일관성 보증이 필요한 비즈니스 도구 등)의 등록 방법으로도 사용됩니다. 다단계 트랜잭션 래핑, 컴플라이언스 심사, 신용 승인과 같은 강한 일관성 비즈니스 시나리오에 적합합니다.

**2.0의 새로운 기능**:

- SkillsHub 원격 로딩: 버전이 관리 플랫폼에 의해 통합적으로 거버넌스됩니다. 서비스 시작 시 게시된 모든 스킬이 전체적으로 풀되며; 관리 플랫폼이 런타임 중 변경 사항을 게시할 때, 전체 프로세스는 다운타임 없이 이루어지며, 버전 관리와 카나리 배포를 지원합니다.
- 자동 스킬 권한 필터링: 사용자의 스킬 사용 권한을 거버넌스하기 위해 NONE, FILTER, REJECT의 세 가지 모드를 지원합니다.

### 4.7 도구 및 지식 통합: 엔터프라이즈 레거시 자산에 대한 표준화된 연결

**시나리오 페인 포인트**: 수년간의 정보화를 거치면서 금융 기관은 많은 비즈니스 시스템과 지식 자산을 축적했지만, 인터페이스 표준이 제각각이고 서로 다른 플랫폼에 흩어져 있어 시스템별 어댑터 코드를 작성하는 데 비용이 많이 듭니다. 한편 방대한 양의 비정형 지식은 에이전트가 효과적으로 활용하기 어렵습니다.

**해결책**: 표준화된 프로토콜과 구성 기반 접근 메커니즘을 통해, 도구 통합, 지식 검색, 권한 전파를 플랫폼 수준의 기반 역량으로 통합하여 적응 노력을 최소화합니다.

**도구 접근**: MCP(Model Context Protocol)와 API Schema라는 두 가지 표준 구성 방식을 제공합니다. 기업은 서비스 주소와 인증 정보만 선언하면 도구 등록을 완료할 수 있습니다. McpClientRegistry는 모든 MCP 연결의 구성, 헬스 체크, 생명주기를 통합적으로 관리하여 도구 가용성을 보장하며; MCP 프로토콜을 준수하는 고객 정의 Bean에 대한 구성 기반 접근도 지원하여, 추가 개발 없이 고객의 레거시 시스템 역량에 매끄럽게 연결됩니다.

**지식 접근**: 통합된 Knowledge 인터페이스가 여러 지식 소스에 걸친 구성 기반 라우팅을 지원합니다 — Bailian 범용 RAG, Dianjin 금융 도메인 지식 베이스, 고객이 구축한 지식 베이스 모두 구성을 통해 연결할 수 있습니다. 에이전트는 통합된 Knowledge 도구를 통해 지식 검색을 호출하며; 하부 계층은 지식 베이스 간의 구현 차이를 자동으로 숨기고 태그 검색, 회상 재순위, 쿼리 재작성과 같은 핵심 역량에 대해 통합된 품질 표준을 설정합니다.

**권한 전파**: 엔터프라이즈 보안 시스템에 매끄럽게 연결됩니다. 도구 호출과 지식 회상 인터페이스에 표준화된 데이터 전파 채널을 제공하여, 신원 정보와 채널 식별자 등의 컨텍스트를 종단 간 전달할 수 있게 함으로써, 에이전트가 수행하는 모든 외부 호출이 사용자의 권한 경계를 자동으로 상속받도록 하며, 인증 로직을 반복해서 재구축할 필요가 없습니다.

**2.0의 새로운 기능**: McpClientRegistry가 동적 관리를 지원합니다: 도구 연결의 추가, 제거, 수정을 런타임에 수행할 수 있으며, 서비스 재시작 없이 몇 초 안에 적용됩니다; 새로 등록된 도구는 자동으로 Agent의 사용 가능 목록에 주입되어, 운영 팀이 독립적으로 도구를 온라인/오프라인으로 전환할 수 있습니다.

### 4.8 접근 게이트웨이 엔진: 통합 다중 채널 진입과 보안 제어

**시나리오 페인 포인트**: 다중 채널 입력 형식이 제각각이어서 통합 처리가 필요하며, Prompt 주입과 같이 AI 시스템이 직면하는 보안 위협은 진입 계층에서 통합 보호가 필요합니다.

- **프로토콜 파편화**: 서로 다른 클라이언트(웹/모바일/서드파티 시스템)가 서로 다른 형식으로 요청을 제출하여, 백엔드가 각각에 적응해야 합니다.
- **보안 위협**: Prompt 주입, 민감한 콘텐츠 입력, 정책 위반 작업 — 진입 계층에서 통합적으로 차단되지 않으면 의도 엔진과 실행 엔진으로 확산되어 통제 불가능한 리스크를 야기합니다.
- **멀티모달 전처리 부재**: 이미지/비디오/오디오/문서와 같은 비정형 콘텐츠가 LLM에 직접 전달되면 효과적으로 이해될 수 없습니다; Prompt를 강화하려면 게이트웨이 계층에서 콘텐츠 추출을 완료해야 합니다.
- **일관되지 않은 스트리밍 출력**: 서로 다른 처리 분기(순수 텍스트/멀티모달/TodoList)마다 자체 SSE 이벤트 형식과 생명주기 관리가 있어, 프론트엔드 통합 비용이 높습니다.
- **느슨한 세션 상태 관리**: 메시지 영속화, 세션 제목 생성, 컨텍스트 복원이 모듈 전반에 흩어져 있어, 통합된 오케스트레이션 지점이 부족합니다.

**해결책**: 프로토콜 적응, 멀티모달 처리, 보안 제어, 요청 라우팅, 스트리밍 출력 오케스트레이션, 세션 영속화라는 여섯 가지 핵심 책임을 구현합니다. 완전한 인터셉터 체인과 권한 검사를 통합합니다. 보안 정책은 관리 콘솔에서 동적 구성을 지원하며, 변경 사항은 몇 초 안에 적용됩니다.

- **프로토콜 적응**: 4가지 입력 형식과 호환되며, 표준 내부 표현으로 통합 파싱됩니다.
- **멀티모달 처리**: 이미지 이해, 비디오 이해, 오디오 ASR, 문서 파싱 — Prompt를 강화하기 위해 병렬로 추출됩니다.
- **보안 제어**: 정책 매칭 + 리스크 채점 + 작업 실행(통과/경고/차단), 화이트리스트와 5분 정책 캐시를 지원합니다.
- **요청 라우팅**: 3방향 디스패치: 순수 텍스트 → OneAgent / 멀티모달 → 추출 + OneAgent / TodoList → 직접 실행.
- **스트리밍 출력 오케스트레이션**: 통합된 AG-UI Protocol 이벤트 형식, 중복 제어 이벤트 필터링, 게이트웨이 계층에서 통합적으로 생명주기 이벤트를 발행.
- **세션 영속화**: 사용자 메시지/어시스턴트 응답이 자동으로 저장되고, 세션 제목이 자동 생성되며, 멀티모달 콘텐츠에는 폴백 저장소가 있습니다.

**2.0의 새로운 기능**: DocumentParserService의 다중 형식 문서 파싱(PDF/DOCX/DOC/MD/TXT)으로, 대용량 파일 청킹, 형식 충실도, 메타데이터 추출을 지원하여 사용자가 업로드한 문서를 기반으로 에이전트와 직접 대화할 수 있도록 함; 여기에 권한 제어 시스템, TodoList 지능형 라우팅, 관측 가능성 계측이 추가됨.

### 4.9 TodoList 작업 관리(2.0에서 신규 구축): 장기 프로세스 작업을 위한 시각화된 진행 추적

**시나리오 페인 포인트**: 국경 간 송금, 대출 승인(30초에서 몇 분 소요)과 같은 장기 프로세스 금융 작업을 대상으로, 사용자에게 Agent의 실행 과정이 "완전히 보이지 않는" 문제를 해결합니다 — 얼마나 진행되었는지 모르고, 분해가 올바른지 모르며, 중단 후 이어갈 수 없습니다.

- **진행 가시성**: 실행 상태(예: "4개 중 2개 완료, 3단계 실행 중")를 실시간으로 동기화하여, 대기 불안을 없애고 불필요한 후속 질문을 줄입니다.
- **검증 가능한 계획**: Agent의 작업 분해 로직을 투명하게 만들어, 사용자가 실행 전이나 중에 누락이나 편차를 식별하고 개입하여 경로를 수정할 수 있게 함으로써 — 수동적인 대기를 능동적인 검토로 전환합니다.
- **재개 가능한 중단**: 작업 상태의 영속적 저장으로 세션/일 단위의 자동 재개를 지원하여, 복잡한 비즈니스 프로세스의 연속성을 보장합니다.

**해결책**: 2단계 스텝 모델 + Hook 자동 주입 + Pipeline 상태 동기화를 기반으로, 계획에서 복구까지의 실행 폐루프를 구축합니다.

**2단계 스텝 관리**: 레벨 1은 LLM이 최상위 스텝 시퀀스(예: "조회 → 검증 → 확인 → 이체")를 자율적으로 분해하도록 하며, TodoListToolkit이 제공하는 7개의 표준 도구를 통해 5개 상태의 전체 생명주기를 관리합니다; 레벨 2는 실행 엔진이 Pipeline 수준에서 자동으로 채워, 병렬로 스케줄링된 하위 Agent의 이름, 작업, 상태를 해당 레벨 1 스텝의 subSteps에 기록하여, 멀티 에이전트 협업의 세부사항을 시각화합니다. 프레임워크는 일관성 제약을 내장하고 있습니다: finish_todo_step을 통한 완료 표시는 필수이며, 동시성 혼란을 방지하기 위해 한 번에 하나의 스텝만 IN_PROGRESS로 허용되고, 스텝이 완료되면 엔진이 자동으로 다음 TODO 스텝을 활성화하여, 자연스러운 상태 전이를 달성하고 Agent 오케스트레이션 복잡도를 크게 줄입니다.

**Hook 자동 상태 주입(감지 불가능한 메모리)**: TodoListHintHook은 PreReasoningEvent를 가로채어 매 LLM 추론 라운드 전에 고정된 도구 설명과 실시간 작업 상태(진행 통계 및 현재/다음 스텝 세부사항 등)를 포함하는 시스템 프롬프트를 동적으로 추가하여, Agent가 독립적인 메모리 모듈 없이도 전체 진행 상황을 "감지 불가능하게" 인지할 수 있게 하고, 작업 완료 후 자동으로 요약 단계로 안내합니다.

**Pipeline 전략을 위한 멀티 에이전트 상태 동기화**: 하위 Agent의 할당과 완료 이벤트를 리스닝하는 ParallelAgentStrategy 엔진을 기반으로, updateTodoSubStepStatus를 자동으로 호출하여 상태를 TodoList 저장소에 동기화함으로써, 메인 Agent가 Hint Hook을 통해 하위 작업 진행 상황을 즉시 인지할 수 있게 하여, 통신 비용 제로로 효율적인 멀티 에이전트 오케스트레이션 상태 동기화를 달성합니다.

## 06 Pro-Code와 Low-Code의 협업

### 6.1 Pro-Code와 Low-Code의 포지셔닝을 올바르게 이해하기

금융 산업에서 "pro-code냐 low-code냐"는 양자택일의 문제가 아니라 "어느 단계, 어느 시나리오에서 어떤 도구를 사용할 것인가"의 문제입니다. 이 둘은 본질적으로 동일한 기술 시스템 내에서 서로 다른 역할을 하며, 에이전트가 "아이디어"에서 "프로덕션"에 이르는 여정의 서로 다른 단계를 담당합니다.

**Low-code 플랫폼의 핵심 장점과 적용 시나리오**: 시각적 오케스트레이션은 비즈니스 담당자가 설계에 직관적으로 참여할 수 있게 하며; 빠른 프로토타이핑은 아이디어를 빠르게 데모로 만들 수 있게 하고; 보는 대로 얻는 디버깅은 문제 식별을 직관적으로 만듭니다. Low-code 플랫폼은 비즈니스 검증 단계에 가장 적합한 선택이며, 변경 빈도가 낮고 프로세스 체인이 짧으며(5-10단계 이내) 신뢰성 요구사항이 비교적 관대한 시나리오에도 적합합니다.

**Low-code가 직면하는 과제**: 시나리오가 복잡한 워크플로 오케스트레이션, 다중 턴 상호작용과 세션 간 상태 관리, AI 자율 계획, 금융급 프로덕션 보증을 포함할 때, low-code 플랫폼의 유지보수 비용과 구축 복잡도가 급증합니다.

### 7.3 관측 가능성 시스템

FinXScope는 접근, 의도, 에이전트 실행을 아우르는 전체 링크 관측 가능성 시스템을 제공합니다. 핵심 기능은 다음과 같습니다.

**분산 추적**: Micrometer Tracing을 기반으로 한 전체 링크 추적으로, 각 요청에 대해 고유한 traceId를 자동으로 생성하며, 게이트웨이 접근부터 Agent 실행까지 전체 생명주기에 걸쳐 있습니다. traceId는 모든 로그 출력에 자동으로 주입되며, 비동기 스레드 간 컨텍스트 전파를 지원하여, 분산 환경에서 요청 체인을 빠르게 찾아내고 문제를 해결하기 쉽게 합니다.

**비즈니스 메트릭 모니터링**: 통합된 BizLogger API를 통한 비즈니스 계측이 표준 Prometheus 메트릭을 자동으로 생성합니다. 메트릭 시스템은 시스템 아키텍처에 따라 6계층(접근 계층, 프레젠테이션 계층, 의도 계층, 실행 계층, 도구 계층, 지식 계층)으로 나뉘며, 각 계층은 이벤트 수, 지연 시간 통계, 활성 요청 수, 오류 분류 등의 차원을 아우르는 메트릭 열거형을 독립적으로 정의합니다. 별도의 관리 포트가 Prometheus Server 스크래핑을 위한 `/actuator/prometheus` 엔드포인트를 노출합니다.

**Agent 생명주기 관측 가능성**: AgentScope Hook 메커니즘과 깊이 통합되어, ObservabilityHook을 사용해 Agent 실행의 5가지 생명주기 단계를 추적합니다: 호출 진입, LLM 추론, 도구 실행, 요약 생성, 예외 처리. 각 단계는 지연 시간과 토큰 사용량을 자동으로 수집하며, 3단계 스위치 제어(전역 스위치 → 이벤트 유형 스위치 → Agent 수준 오버라이드)를 지원하여, 프로덕션 환경에서 특정 Agent나 특정 단계에 대한 관측 데이터 수집을 필요에 따라 켜고 끌 수 있게 합니다.

**구조화된 로깅**: BizLogger는 이중 모드 로그 출력을 제공합니다: 각 비즈니스 로그는 사람이 읽기 쉬운 형식으로 콘솔에 출력되는 동시에, 구조화된 JSON 형식으로 별도의 파일에 기록됩니다. 로그는 traceId, sessionId, userId와 같은 컨텍스트 정보를 자동으로 포함하여, 기계 파싱과 로그 플랫폼 통합을 지원합니다.

**SPI 확장 메커니즘**: 프레임워크는 3계층의 SPI 확장 지점을 제공하여, 프레임워크 코드를 수정하지 않고도 사용자가 관측 가능성 동작을 커스터마이징할 수 있게 합니다.

- 로그 출력 확장: 사용자 정의 BizLoggerProvider를 등록하여 기본 로그 처리 로직을 대체하거나 보완.
- Hook 등록 확장: AgentHookProvider를 구현하여 Agent에 사용자 정의 생명주기 훅을 주입.
- 데이터 추출 확장: HookLogFormatter를 구현하여 Hook 이벤트에 대한 데이터 추출과 포맷팅 로직을 커스터마이징.

### 8.2 배포 모드와 리소스 산정

**1. FinXScope는 두 가지 사용 모드를 지원합니다:**

- **독립 실행형 애플리케이션**: 실행 가능한 Fat JAR / Docker 이미지로 패키징되어, 독립적으로 실행되며 외부에 API를 제공합니다.
- **의존성 임포트**: Maven을 통해 다른 애플리케이션이 Spring Boot Starter로 임포트하며, Agent 역량이 자동으로 연결됩니다.

**2. FinXScope의 런타임은 항상 구체적인 시나리오 애플리케이션에 부착됩니다:**

**독립 실행형 애플리케이션으로서**, FinXScope 자체가 시나리오 애플리케이션이며, 컨테이너화되어 직접 배포되어 외부에 서비스를 제공합니다.

**임포트된 의존성으로서**, FinXScope는 호스트 시나리오 애플리케이션과 함께 패키징되고 배포되며, 독립적인 런타임 인스턴스가 필요하지 않습니다; 그 리소스 소비는 호스트 애플리케이션에 포함됩니다.

**구체적인 시나리오 애플리케이션이 없는 경우:**

- 코드 저장소의 참조 구현/소스 코드입니다.
- Maven 저장소의 의존성 패키지(JAR)입니다.

즉, FinXScope는 시나리오에서 분리된 독립적인 "상시 가동" 상태를 가지지 않습니다. 배포 계획은 실제 시나리오 애플리케이션을 중심으로 세워야 합니다.

## 09 FinXScope 2.0 버전 진화

FinXScope 2.0은 "단일 에이전트 런타임 프레임워크"에서 "엔터프라이즈급 에이전트 런타임 및 관리 플랫폼"으로의 도약을 완성합니다.

- **멀티 에이전트 협업 시스템(신규 구축)**: 8가지 오케스트레이션 전략을 지원하는 통합 워크플로 실행 엔진; OneAgent로의 워크플로 마운팅(MountableResource 메커니즘); 하위 프로세스 이벤트 패스스루(GraphNodeEmitter); DAG 그래프 실행기(위상 정렬, 계층 내 병렬, 계층 간 순차).
- **권한 및 보안 시스템(신규 구축)**: User-Agent-Skill 3단계 권한, FILTER/REJECT 이중 모드, 권한 캐시 최적화, fail-open/fail-close 내결함성. JWT 인증 통합.
- **관측 가능성 시스템(신규 구축)**: BizLogger 이중 모드 출력, ObservabilityHook 자동 관측, BizLoggerProvider SPI 확장.
- **고가용성과 상태 비저장(주요 업그레이드)**: STM → Redis, LTM → PostgreSQL, 구성 핫 업데이트 엔진(Redis Pub/Sub + ConfigVersionRegistry), 완전 상태 비저장.
- **의도 계층 강화**: 런타임 의도 트리 오버라이드, 런타임 모델 오버라이드, 의도 트리 관리 API(CRUD + 버전 롤백 + 의도 스위치 추적).
- **접근 계층과 프레젠테이션 계층 강화**: 게이트웨이 엔진 리팩터링, DocumentParserService 다중 형식 문서 파싱, workflow_command_agent, WorkflowToolRegistry 동적 도구 주입.
- **TodoList 작업 관리(신규 구축)**: 2단계 스텝 관리, 7개 도구, Hook 자동 주입, Pipeline 통합.
- **MCP 구성 관리 강화**: McpClientRegistry 동적 관리, CustomMcpToolsInjector 자동 주입, 구성 동기화.
- **HITL 인간 개입 시스템**: 민감한 작업에 대한 도구 수준 인터셉션과 인간 확인; Agent 메모리 스냅샷과 재개 가능한 중단점; 일시 중단 상태의 분산 영속화; 사용자 확인/거부 의도의 자동 판정.
- **A2A 멀티 에이전트 협업 프로토콜**: 표준 Agent-to-Agent 프로토콜 서버 및 컨슈머 측; 자동 AgentCard 생성과 다중 모드 서비스 디스커버리; 동기/스트리밍 이중 채널 Agent 간 호출; AG-UI와 A2A 간 양방향 이벤트 변환; Nacos 레지스트리 통합과 동적 새로고침.
- **샌드박스 보안 실행 시스템**: 여러 주류 샌드박스 백엔드 지원; 비동기 샌드박스 생성과 세션 수준 인스턴스 재사용; 파일 업로드/다운로드와 워크스페이스 동기화; 명령 실행 격리와 타임아웃 제어; 스킬 리소스의 자동 배포와 킵얼라이브 관리.

## 11 요약과 전망

FinXScope는 금융급 에이전트 기반의 완전히 새로운 패러다임을 대표합니다. "만능 AI 애플리케이션"이 되려고 시도하지 않으며, 한 가지를 제대로 하는 데 집중합니다: 금융 기관에 신뢰할 수 있고, 고성능이며, 확장하기 쉬운 에이전트 런타임 및 관리 기반을 제공하여, 어떤 금융 애플리케이션이든 매우 낮은 비용으로 AI 네이티브 역량을 얻을 수 있도록 하는 것입니다.

FinXScope의 기반은 전적으로 AgentScope Java 2.0 위에 구축되어, 엔터프라이즈급 프로덕션 환경을 위한 핵심 역량을 깊이 재사용합니다 — ReAct 추론-행동 루프, 5단계 미들웨어 체인, 통합 메시지 모델과 타입이 지정된 이벤트 스트림, 도구 및 스킬 프레임워크, 계층화된 메모리와 상태 영속화, 3상태 권한 엔진, 우아한 종료와 인터럽트 메커니즘을 포함합니다. 이를 기반으로 FinXScope는 금융 산업의 컴플라이언스 감사, 데이터 보안, 고가용성 요구사항에 대해 체계적인 산업별 강화를 수행합니다.

FinXScope의 핵심 가치를 돌아보면: 6계층 표준화 아키텍처는 엔터프라이즈 AI 구축을 위한 명확한 아키텍처 청사진과 계획 경로를 제공합니다; 이중 모드 실행 아키텍처는 유연성과 제어 가능성 사이에서 최적의 균형을 찾습니다; 구성 주도 설계는 pro-code의 높은 역량 상한선과 낮은 사용 장벽을 결합합니다; 고가용성, 보안 컴플라이언스, 관측 가능성의 엔터프라이즈급 보증은 금융급 프로덕션 배포를 더 이상 어려운 문제가 아니게 만듭니다.

1.0에서 2.0까지, FinXScope는 "단일 에이전트 프레임워크"에서 "엔터프라이즈급 에이전트 런타임 및 관리 플랫폼"으로의 도약을 완성했습니다. 멀티 에이전트 협업 시스템, 권한 및 보안 시스템, 관측 가능성 시스템, 구성 관리 플랫폼과 같은 핵심 역량의 추가는 이제 금융 기관에서 규모화된 에이전트 배포를 지원할 수 있는 완전한 역량을 갖추었음을 의미하며, 금융 기업의 지능형 전환을 위한 견고한 기반을 제공합니다.
