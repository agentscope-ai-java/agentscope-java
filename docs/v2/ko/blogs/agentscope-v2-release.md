title: "AgentScope 2.0: 투명한 개발에서 시스템 엔지니어링으로"
---

AgentScope는 에이전트 애플리케이션을 구축하기 위한 오픈소스 프레임워크로, 개발자가 대규모 언어 모델에서 배포 가능한 에이전트로 나아가도록 돕는다. 오늘날의 과제는 더 이상 단순히 에이전트가 단일 요청에 응답하도록 만드는 것이 아니라, **작업을 신뢰성 있게 완료하도록** 만드는 것이다. 길고 다단계인 워크플로를 처리하고, 도구를 안전하게 호출하며, 외부 시스템과 깔끔하게 통합하는 것이다.

이러한 필요를 충족하기 위해 AgentScope 1.0은 *투명한 개발*이라는 아이디어를 도입했다. 에이전트가 메시지를 받고, 도구를 호출하고, 협업자와 조율하는 모든 단계가 개발자에게 보여야 하며, 이는 시스템을 이해하고, 디버깅하고, 확장하는 비용을 낮춘다. AgentScope 2.0은 이 원칙을 그대로 이어가면서 프로덕션의 현실 — 안정적인 실행, 통제된 자율성, 깔끔한 통합 — 에 더욱 진지하게 초점을 맞춘다. 그 결과는 더 완전하고 더 응집력 있는 시스템 레벨의 업그레이드다.

## 1. 모델 통합: 개방형 생태계 위의 장애 허용

![모델 통합: 개방형 생태계 + 재시도 및 폴백 모델](/imgs/v2/as2-release-02.png)

AgentScope 2.0은 1.0의 개방형 모델 계층 — Qwen, Anthropic, DeepSeek, Gemini, OpenAI — 을 유지하면서 Grok, Moonshot 같은 프로바이더로 이를 확장한다. 하지만 2.0의 진짜 초점은 "더 많은 모델"이 아니다. 모델 호출을 **복잡한 워크로드에서도 안정적으로** 만드는 것이다.

실제 작업에서 에이전트는 일반적으로 여러 라운드의 추론을 실행하고 여러 도구 호출을 트리거한다. 실패하거나, 타임아웃되거나, 사용 불가능한 모델 응답 하나가 나머지 실행 전체를 망칠 수 있다. 그래서 AgentScope 2.0은 모델 계층에 통일된 재시도 및 폴백 모델 메커니즘을 도입한다. 개발자는 최대 재시도 횟수와 폴백 모델을 설정할 수 있으며, 기본 모델이 실패하면 프레임워크가 자동으로 폴백을 시도하여 작업이 계속 진행되도록 한다.

이 업그레이드는 에이전트가 더 이상 단순히 "모델을 호출할 수 있는" 존재가 아니라는 것을 의미한다 — 이제 모델과 대화하기 위한 더 견고한 런타임 전략을 갖추게 된다. 지속적인 추론과 다단계 실행에 의존하는 작업의 경우, 모델 계층의 안정성은 에이전트가 애초에 작업을 완료할 수 있는지를 좌우하는 기반이 된다.

## 2. 메시지와 이벤트: 채팅 문자열에서 상호작용형 실행 스트림으로

![통합 메시지 구조 → 이벤트 스트림 → UI가 실시간으로 따라간다](/imgs/v2/as2-release-03.jpg)

에이전트 애플리케이션의 복잡성은 메시지에서도 드러난다. 채팅 앱에서는 메시지가 단순한 문자열일 수 있다. 에이전트 실행 내부에서는 하나의 메시지가 텍스트, 이미지, 파일, 도구 호출, 도구 결과, 모델의 사고 과정, 사용자 확인 상태, 또는 외부 실행 결과를 담을 수 있다. AgentScope 2.0은 메시지 모듈을 재설계하여 이 모든 것이 통일된 `Content Block`을 통해 흐르도록 한다. 그 안에서 `DataBlock`은 base64와 URL 데이터 소스를 모두 지원하여, 서로 다른 모델 API의 멀티모달 및 파일 기능과 더 쉽게 정렬되도록 한다.

이 기반 위에서 AgentScope 2.0은 이벤트 시스템을 도입한다. 에이전트의 단일 응답은 더 이상 단순한 최종 문자열이 아니다 — 모델 호출 시작, 텍스트 델타, 도구 호출, 도구 결과, 사용자 확인, 외부 실행 업데이트 같은 이벤트를 스트리밍할 수 있다. 이를 통해 프런트엔드 UI는 에이전트의 작업을 실시간으로 렌더링할 수 있으며, 사람의 확인, 사람의 개입, 외부 도구 실행이 프레임워크의 일급 기능이 된다. 예를 들어 에이전트가 민감한 도구를 호출하려 할 때 사용자 확인을 발생시킬 수 있으며, 도구가 외부 환경에서 실행될 때 에이전트는 외부 결과를 기다린 다음 작업을 계속할 수 있다.

따라서 메시지 모듈과 이벤트 시스템에 대한 업그레이드는 AgentScope의 "투명함" 원칙을 강화하는 것 이상을 한다. 이는 에이전트의 실행을 **관찰 가능하고, 상호작용 가능하며, 중단 가능하게** 만든다. 개발자가 보는 것은 더 이상 최종 답변만이 아니다 — 펼쳐지는 대로 지켜보고 조종할 수 있는 실행 스트림이다.

## 3. 권한 시스템: 경계가 있는 자율성

![권한 시스템: 정적 규칙 + 도구 유형 + 입력 분석 → 허용 / 확인 / 거부](/imgs/v2/as2-release-04.png)

대규모 모델을 최대한 활용하려면 에이전트에게 진정한 자율성이 필요하다 — 단순히 응답을 생성하는 것이 아니라, 작업 진행 상황에 따라 도구를 능동적으로 선택하고, 정보를 읽고, 행동을 취하는 것. 에이전트가 자율적일수록, 무엇을 할 수 있는지에 대한 명확한 경계를 긋는 것이 더욱 중요해진다.

AgentScope 2.0은 에이전트가 도구를 호출하고, 파일을 읽고 쓰고, 명령을 실행하는 방식을 통제하는 더 체계적인 권한 시스템을 도입한다. 도구 호출은 더 이상 단순한 이진(허용/거부) 결정이 아니다. 정적 규칙, 도구 유형, 실제 입력을 기반으로 AgentScope는 작업을 허용할지, 거부할지, 또는 사용자 확인으로 에스컬레이션할지 결정할 수 있다. 파일시스템 도구는 위험한 디렉터리와 민감한 파일을 검사하고, 명령 도구는 고위험 명령, 동적 셸 구문, 파괴적인 삭제를 분석한다. 알려지지 않았거나 고위험인 행동의 경우, AgentScope는 자동으로 호출을 사용자 승인 흐름으로 라우팅할 수 있다.

이 시스템을 통해 에이전트는 더 이상 단순히 "도구를 호출할 수 있는" 존재가 아니다 — **명시적이고 통제 가능한 경계 안에서** 자율적으로 행동할 수 있다. 지속적인 도구 사용, 파일 접근, 명령 실행에 의존하는 복잡한 작업의 경우, 이 안전 경계는 에이전트가 안정적으로 작업을 완료할 수 있는지를 좌우하는 또 하나의 기반이 된다.

## 4. 재구축된 컨텍스트 관리: 긴 작업과 성능 지원

![컨텍스트 관리: 구조화된 압축 + 도구 결과 오프로드 + 파일 I/O 캐시](/imgs/v2/as2-release-05.png)

긴 작업을 처리하는 것은 에이전트 애플리케이션을 실제 세계로 가져오는 데 있어 가장 중요한 단계 중 하나다. 긴 작업은 여러 라운드의 모델 호출, 많은 도구 결과, 큰 파일 콘텐츠, 지속적인 사용자 피드백을 포함할 수 있다. 컨텍스트 관리가 "히스토리를 윈도우 안으로 압축한다"에서 멈춘다면 새로운 문제들이 금방 나타난다 — 어떤 정보를 유지해야 하는지, 어떤 도구 결과를 절단해야 하는지, 같은 파일을 다시 읽는 것을 어떻게 피할지, 긴 실행 체인 전반에서 작업 상태를 어떻게 일관되게 유지할지.

AgentScope 1.0은 이미 컨텍스트 관리 기능을 제공했다. 2.0에서는 이러한 기능들이 더 체계화된다. AgentScope 2.0은 작업 상태, 도구 결과, 파일 I/O와 함께 컨텍스트를 관리한다 — 압축은 더 이상 평면적인 요약이 아니다. 작업 목표, 현재 상태, 핵심 발견, 다음 계획, 그리고 장기적으로 보존해야 하는 정보를 구조화된 방식으로 유지한다. 도구 결과는 절단되어 지나치게 큰 로그, 검색 결과, 파일 콘텐츠가 컨텍스트 윈도우를 폭발시키지 않도록 한다. 내장 파일 도구는 반복적인 I/O를 줄이기 위해 읽기 캐시를 추가하며, 기존 파일을 편집하는 작업은 먼저 파일을 읽어야 하도록 요구하여 성능과 운영 신뢰성을 모두 개선한다.

AgentScope 2.0에서 컨텍스트 관리는 더 이상 단순히 "히스토리를 압축한다"가 아니다. 이는 **긴 작업 실행을 지속시키기 위한 시스템 레벨의 전략**으로 업그레이드된다. 이를 통해 에이전트는 더 체계적인 방식으로 작업 상태를 유지하고, 컨텍스트가 얼마나 커지는지 통제하며, 지속적인 추론과 반복적인 도구 호출 전반에서 안정성을 유지할 수 있다.

## 5. 미들웨어: 더 유연한 확장 표면

![미들웨어: 에이전트의 핵심 실행 단계에 후킹한다](/imgs/v2/as2-release-06.png)

실제 에이전트는 종종 자신만의 로깅, 권한 정책, 비즈니스 컨텍스트, 모델 호출 전략을 필요로 한다. 이런 기능 하나하나를 프레임워크 내부를 수정해서 추가해야 한다면, 확장 비용이 올라갈 뿐 아니라 프레임워크의 안정성에 대한 위험도 커진다.

AgentScope 2.0은 개발자가 에이전트의 핵심 실행 단계에 커스텀 로직을 주입할 수 있게 해주는 **미들웨어** 메커니즘을 도입한다 — 모델 호출 전후의 로그 추적, 도구 실행 전의 보안 검사, 추론-행동 루프 내부의 비즈니스 정책, 시스템 프롬프트 구성 단계에서의 동적 컨텍스트 주입. 미들웨어는 AgentScope 2.0이 핵심 프레임워크를 안정적으로 유지하면서도 실제 애플리케이션이 요구하는 변형들을 위한 충분한 여지를 남겨두게 해준다. 이는 또한 2.0이 1.0의 투명성 원칙을 이어가는 방식이기도 하다 — 프레임워크는 블랙박스가 아니며, 개발자는 이를 명확히 이해하고 그 안으로 들어갈 수 있다.

## 6. Workspace: 실행 환경과 에이전트 로직의 분리

![Workspace: "에이전트가 무엇을 하는가"와 "어디서 실행되는가"를 분리한다](/imgs/v2/as2-release-07.png)

에이전트가 더 유능해질수록, 단순히 모델을 호출하는 것에 그치지 않는다 — 도구를 사용하고, 파일에 접근하고, Skill을 로드하고, MCP 서비스와 대화하고, 서로 다른 환경에서 작업을 실행해야 한다. 이 모든 것이 에이전트의 런타임 로직에 고정되어 있다면, 로컬 환경, 컨테이너, 클라우드 샌드박스 사이를 전환할 때마다 반복적인 적응이 강요된다. AgentScope 2.0은 "에이전트가 무엇을 하는가"와 "어디서 실행되는가"를 분리하기 위해 특별히 **Workspace**를 도입하여, 실행 환경이 교체 가능하고 관리 가능한 시스템 컴포넌트가 되도록 한다.

Workspace는 에이전트의 실행 환경에 대한 AgentScope 2.0의 추상화다. 이는 도구, MCP 서비스, Skills 라이브러리, 컨텍스트 지속성을 제공하며, 로컬 파일시스템, Docker 컨테이너, E2B 클라우드 샌드박스 같은 서로 다른 실행 저장소를 단일 인터페이스 뒤로 통합한다. 동일한 에이전트가 런타임 로직을 변경하지 않고도 이 환경들 중 어디에서나 실행될 수 있다. 이 설계는 세 가지로 귀결된다.

**첫째, 통일된 인터페이스.** `WorkspaceBase`는 정체성, 생명주기, 리소스 탐색, 컨텍스트 오프로딩, 동적 리소스 관리를 추상화한다. 각 백엔드는 AgentScope의 실행 시스템에 연결되기 위해 동일한 인터페이스 세트만 구현하면 된다.

**둘째, 결합이 아닌 조합.** 에이전트 자체는 특정 Workspace에 의존하지 않는다. Toolkit과 자신이 받는 지시를 통해 도구와 리소스를 간접적으로 사용한다. 이는 실행 환경을 교체 가능하게 유지하면서도 에이전트의 런타임 로직을 안정적이고 이식 가능하게 유지한다.

**셋째, 풀링 지원.** Workspace는 워밍업 풀과 함께 제공된다 — 실행 환경을 배치로 미리 초기화할 수 있으며, 풀은 획득 / 반환 / 무효화-후-교체 연산을 제공한다. RL 훈련 중 병렬 롤아웃 같은 시나리오에서는 이를 통해 환경을 반복적으로 생성하는 비용을 줄이고 리소스 재사용과 작업 처리량을 개선한다.

Workspace를 통해 에이전트는 더 이상 단순히 "도구를 호출할 수 있는" 존재가 아니다 — **교체 가능하고 관리 가능한 실행 환경** 안에서 계속 작업할 수 있다. 로컬 머신, 컨테이너, 클라우드 샌드박스 사이를 오가야 하는 복잡한 작업의 경우, 이 추상화는 안정적인 운영과 유연한 확장을 위한 또 하나의 기반이 된다.

## 7. Agent Service: 로컬 스크립트에서 배포 가능한 시스템으로

![Agent Service: 표준화된 서비스 인터페이스 + 세션 로그 복구 + 백그라운드 도구](/imgs/v2/as2-release-08.png)

이번 릴리스에서 AgentScope 2.0은 이전에 AgentScope Runtime에 있던 Agent Service 기능을 메인 라이브러리로 병합한다. 이유는 직접적이다 — 실제 사용 사례는 터미널이나 단일 Python 프로세스에서만 실행할 수 있는 에이전트를 필요로 하지 않는다. 프런트엔드, 외부 앱, 워크플로 시스템에서 신뢰성 있게 호출할 수 있는 에이전트가 필요하다.

이전에는 에이전트의 핵심 로직과 런타임 서비스 기능이 서로 다른 스택에 흩어져 있어서, 개발자들이 로컬 개발, API 패키징, 상태 관리, 로그 복구, 샌드박스 실행, 배포를 끊임없이 이어붙여야 했다. 이러한 기능들을 하나로 모음으로써 AgentScope 2.0은 그 간극을 메운다. 그 결과 에이전트는 **처음부터** 서비스 준비가 되고, 복구 가능하며, 관측 가능하고, 안전하게 실행되는 방식으로 구축된다.

표준화된 서비스 인터페이스는 에이전트가 실행 진행 상황을 외부로 스트리밍할 수 있게 해주어, 프런트엔드가 실행을 실시간으로 표시할 수 있다. 세션 로그 복구는 작업이 중단 후에도 이어서 진행될 수 있게 해준다. 백그라운드 도구 실행은 장시간 실행되는 도구가 더 신뢰성 있게 완료될 수 있게 해준다. Agent Service의 병합은 에이전트가 더 이상 단순히 "로컬에서 실행할 수 있는" 존재가 아니라는 것을 의미한다 — 서로 다른 애플리케이션과 실행 컨텍스트에 연결되는 안정적인 서비스로 배포될 수 있으며, 에이전트 시스템의 런타임 지원 계층이 된다.

## 마치며: 투명한 개발에서 시스템 엔지니어링으로

1.0의 *투명한 개발* 원칙을 이어가면서, AgentScope 2.0은 단 하나의 목표를 중심으로 시스템 레벨의 업그레이드를 조직한다 — **에이전트가 작업을 신뢰성 있게 완료하도록 하는 것.** 모델 계층의 재시도 메커니즘부터, 실행 환경의 분리와 추상화까지, 세밀한 권한 경계부터, 표준화된 서비스 통합까지 — 각 업그레이드는 실제 세계의 에이전트가 실제로 필요로 하는 것을 시스템 전반에 걸쳐 다루기 위한 것이다. 장시간 실행, 안전한 도구 사용, 지속적인 작업 진행, 외부 앱과의 깔끔한 통합. 이번 릴리스와 함께 AgentScope의 초점은 "에이전트를 어떻게 만들 것인가"에서 "에이전트를 어떻게 신뢰성 있게 계속 실행되게 할 것인가"로 이동한다.

이번 2.0 릴리스와 함께 AgentScope는 다국어 지원도 확대하고 있다. [Python](https://github.com/agentscope-ai/agentscope) 버전은 이미 2.0으로 업데이트되었으며([https://github.com/agentscope-ai/agentscope](https://github.com/agentscope-ai/agentscope)), 이제 [TypeScript 버전의 AgentScope](https://github.com/agentscope-ai/agentscope-typescript)도 있다([https://github.com/agentscope-ai/agentscope-typescript](https://github.com/agentscope-ai/agentscope-typescript)). AgentScope의 Java 버전도 곧 2.0으로 업데이트될 예정이다.

AgentScope를 기반으로 구축된 에이전트 애플리케이션인 QwenPaw 역시 가까운 시일 내에 AgentScope 2.0 기반으로 업그레이드되어, 사용자에게 더 안정적이고, 더 안전하며, 더 확장 가능한 에이전트 경험을 제공할 예정이다.

AgentScope 2.0은 슈퍼 에이전트 애플리케이션을 위한 더 견고한 시스템 기반을 다지고 있다.
